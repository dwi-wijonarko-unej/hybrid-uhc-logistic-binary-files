# Hybrid Unimodular Hill + Logistic Map XOR Scheme for Binary Files

Experimental evaluation framework for the article
*"Experimental Evaluation of a Hybrid Unimodular Hill and Logistic Map XOR
Scheme for Binary Files"*.

The project implements a file cipher that treats **any file as raw bytes** and
combines two operations per 256-byte block:

1. a **Hill transform** with a 16 × 16 unimodular key matrix over Z/256Z, and
2. a byte-wise **XOR** with a keystream generated by a **logistic map**.

Decryption reproduces the original file bit-for-bit. A reproduction pipeline
measures runtime, byte statistics, and exact reconstruction for a set of test
files and emits all raw measurements, tables, and figures.

> ## ⚠️ Security warning — read this first
>
> This is **not** modern authenticated encryption and must never be used to
> protect real data. It is a *proof-of-concept* built to evaluate
> **reversibility, byte statistics, and runtime** of the studied scheme.
> Specifically:
>
> - No security claims are made against known-plaintext, chosen-plaintext,
>   or any modern cryptanalytic attack. The Hill stage is linear and the
>   logistic map is deterministic in IEEE-754 double precision.
> - There is **no per-file nonce or diversification** in this baseline: the
>   same keystream and the same key matrix are reused for every file and
>   every run. This is a deliberate baseline experimental decision and a
>   documented security limitation — not a production design.
> - There is **no integrity or authentication** (no MAC/tag); ciphertexts are
>   malleable.
> - Key material lives in a plaintext YAML file.
> - Logistic maps in finite precision have short cycles and orbit
>   collisions; the quantization `floor((x*1000) mod 256)` does not produce
>   a uniform byte distribution.

## Purpose and scope

Evaluate, reproducibly and from a single YAML configuration:

- **exact reversibility** of the encrypt→decrypt roundtrip (SHA-256 and MD5),
- **byte statistics** of plaintext vs ciphertext (Shannon entropy,
  adjacent-byte correlation, chi-square against uniformity),
- **runtime** (encryption/decryption time and throughput per file size),
- **ciphertext expansion** (expected to be exactly zero).

Out of scope: any claim of cryptographic security. Out of scope: AES, RSA, or
any other standard cipher — the implementation uses only the studied
unimodular Hill transform and the logistic-map XOR.

## Algorithm specification

All parameters below are read from `config/experiment_config.yaml`; there are
no hidden defaults and no interactive input.

### Key material (unimodular 16 × 16 matrix)

1. Generate a logistic byte sequence of length
   `sequence_length = n(n-1)/2 + (n-1)` = **135** for `n = 16`
   (same recurrence and quantization as the keystream below, including the
   warm-up).
2. Initialize `M = I_n` (integer identity).
3. Fill the strict upper triangle in row-major order:
   `M[i, j] = sequence[index]`, `index += 1` for all `i < j`.
4. Fill the lower part with determinant-preserving elementary row additions:
   for `row_i` in `1..n-1`: `multiplier = sequence[index]`,
   `M[row_i, :] = (M[row_i, :] + multiplier * M[0, :]) mod 256`, `index += 1`.
   Because the construction starts at the identity and only applies
   `R_i ← R_i + a·R_0`, the determinant stays exactly 1, so
   `det(M) ≡ 1 (mod 256)` and M is invertible modulo 256.
5. The inverse `M⁻¹` is computed **exactly** with Gauss–Jordan elimination
   over Z/256Z (see below) and verified:
   `(M @ M⁻¹) mod 256 == I` **and** `(M⁻¹ @ M) mod 256 == I`.

Both matrices are exported to `results/configuration/key_matrix.csv` and
`results/configuration/key_matrix_inverse_mod256.csv`.

### Modular matrix inverse (composite modulus 256)

`numpy.linalg.inv` is **never** used (floating point, meaningless modulo
256). The elimination:

- pivots only on units (`gcd(pivot, 256) == 1`), swapping rows when needed;
- raises a clear error when no unit pivot exists (matrix singular mod 256);
- inverts pivots with the **extended Euclidean algorithm**;
- runs on signed 64-bit integers with an explicit `% 256` after every update,
  so no implicit uint8 wrap-around can occur before reduction.

### Logistic-map keystream

- Recurrence: `x_(t+1) = r · x_t · (1 − x_t)` in IEEE-754 binary64
  (Python `float`).
- **1000 warm-up iterations** are discarded before the first byte.
- Quantization: `k_i = floor((x_i · 1000) mod 256)`, stored as `uint8`.
- The generator is **stateful and continuous**: the orbit is never reset per
  block or per file; full blocks consume keystream bytes
  `[0, n_full·256)` and the tail consumes the remaining bytes.
- Identical parameters always produce byte-identical keystreams (unit-tested).

### Encryption

1. Read the file as raw bytes.
2. Split into full 256-byte blocks plus a residual tail.
3. For each full block: reshape row-major to 16 × 16 (`P_i`), compute
   `H_i = (M @ P_i) mod 256`, serialize `H_i` row-major to 256 bytes, and
   XOR with the next 256 keystream bytes.
4. The residual tail (< 256 bytes) never passes through the Hill matrix
   (incomplete dimensions); it is only XORed: `C_tail = P_tail ⊕ K_tail`.
5. Ciphertext length **always equals** plaintext length (zero expansion).
   Output is written as a raw binary file.

### Decryption

Symmetric, with the identical parameters and the same initial logistic
setting: XOR with the identical keystream first, then apply `M⁻¹` to every
full block (`P_i = (M⁻¹ @ H_i) mod 256`); the tail is XORed back. Exact
reconstruction is verified with SHA-256 (MD5 is additionally recorded for
legacy compatibility; SHA-256 is authoritative).

## Requirements and setup

- Python **3.10** (also runs on newer CPython; the code avoids 3.11+-only syntax).
- Dependencies: NumPy, SciPy, Matplotlib, PyYAML (runtime) and pytest (tests).
  Nothing else.

**venv (pip):**

```bash
python3.10 -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

`requirements.txt` pins the Python 3.10 baseline (`numpy==1.26.4`,
`scipy==1.11.4`, `matplotlib==3.8.4`, `PyYAML==6.0.1`, `pytest==8.1.1`) and
contains environment markers that resolve compatible wheels on newer
interpreters. All numeric results are identical across both branches because
every computation is deterministic.

**conda:**

```bash
conda env create -f environment.yml
conda activate hybrid-uhc-logistic
```

The experiment environment (interpreter, package versions, OS, CPU) should be
recorded alongside any published numbers — see *Limitations*.

## Usage

Run everything from the repository root.

**Unit tests:**

```bash
python -m pytest
```

**Generate the 12 deterministic synthetic placeholder files**
(3 DOCX-like / PDF-like / JPEG-like types × 4 sizes, from
`synthetic_files` in the config):

```bash
python scripts/generate_synthetic_test_files.py --config config/experiment_config.yaml
```

**Reproduce the full experiment** (manifest, raw measurements, byte
statistics, reconstruction checks, key-material report, summary table, and
all figures under `results/`):

```bash
python scripts/reproduce_experiments.py --config config/experiment_config.yaml
```

If `data/input/` is empty, the synthetic files are generated automatically
first (`experiment.generate_synthetic_files_if_missing: true`).

**Encrypt a single file** (metadata JSON optional):

```bash
python scripts/encrypt_file.py \
    --config config/experiment_config.yaml \
    --input data/input/synthetic_pdf_128KB.bin \
    --output results/ciphertexts/manual_pdf.enc \
    --metadata results/ciphertexts/manual_pdf.meta.json
```

**Decrypt a single file and verify exact reconstruction:**

```bash
python scripts/decrypt_file.py \
    --config config/experiment_config.yaml \
    --input results/ciphertexts/manual_pdf.enc \
    --output results/decrypted/manual_pdf.dec \
    --verify-original data/input/synthetic_pdf_128KB.bin \
    --metadata results/decrypted/manual_pdf.meta.json
```

The decrypt script exits non-zero if `--verify-original` is given and the
reconstruction does not match byte-for-byte.

### Revised legacy benchmark on real DOCX / PDF / JPEG files

`scripts/benchmark_real_files.py` is the direct revision of the legacy
monolithic benchmark program (Unimodular Hill + Logistic Map + **Shift
Cipher**). The revision is structural, not cosmetic:

| Legacy program | Revised program |
|---|---|
| Shift Cipher on the tail | **removed**; no Shift Cipher anywhere |
| Tail-only chaotic XOR with a second seed (`x0 + 0.12345`) | one continuous logistic keystream XORs the **entire** Hill output (full blocks *and* tail) from `x0 = 0.73911` |
| Hill over the whole file as one n × columns matrix | Hill per **16 × 16 (256-byte) row-major block** |
| Heuristic elimination for the inverse | exact Gauss–Jordan over Z/256Z with unit pivots + extended Euclid, verified in both product directions |
| Interactive passwords (`PWD1`/`PWD2`) | frozen `CipherParameters` dataclass (constructor/CLI configurable) |
| Keystream re-ran the 1000-iteration warm-up on every call, with NaN fallbacks | stateful stream, warm-up once per operation, strict parameter validation |
| MD5-only integrity | SHA-256 primary (byte-compare confirmed), MD5 secondary |

It keeps the legacy workflow: generates real DOCX (python-docx), valid
hand-built PDF, and real JPEG (Pillow) files padded to target size with
`os.urandom`, then runs the benchmark loop and prints TABLE 1 (entropy /
adjacent-byte correlation), TABLE 2 (times and throughputs), TABLE 3
(integrity), exports `benchmark/summary_results.csv`, and renders the
plaintext/ciphertext histogram figure. The cryptographic core is imported
from `hybrid_crypto`, so it runs exactly the algorithm covered by the unit
tests (bounded-memory chunked processing for large files). `python-docx` and
`Pillow` are auto-installed on first use and are needed **only** for test
file generation, never for the crypto.

```bash
# full default set: DOCX/PDF/JPEG at 1, 10, 50, 100 MB (12 files)
python scripts/benchmark_real_files.py

# quick run: one size class only (3 files)
python scripts/benchmark_real_files.py --target-sizes-mb 1

# reuse already generated files, or force regeneration
python scripts/benchmark_real_files.py --skip-generate
python scripts/benchmark_real_files.py --regenerate
```

Note: `os.urandom` padding makes the generated files realistic but not
bit-reproducible across runs (the legacy program's deliberate choice); the
cryptography itself is fully deterministic for a given input file and
parameter set. Timings include file I/O, use 1 MB = 1,048,576 bytes, and are
hardware-dependent.

| `cipher.modulus` | `256` | Byte algebra modulus (must be 256). |

| `cipher.warmup_iterations` | `1000` | Discarded iterations before the first byte. |
| `cipher.quantization_rule` | `k_i = floor((x_i*1000) mod 256)` | Documentation string echoed into the key report. |
| `cipher.numeric_precision` | IEEE-754 binary64 | Documentation string echoed into the key report. |
| `benchmark.timing_warmup_runs` | `1` | Warm-up runs per file, excluded from statistics. |

| `benchmark.include_file_io_in_timing` | `true` | Time read+transform+write (`false` = transform only). |

## Metric definitions

- **Shannon entropy**: `H = −Σ p_i log2(p_i)` over the 256-value byte
  distribution, in bits/byte.
- **Adjacent-byte correlation**: Pearson r between `data[:-1]` and
  `data[1:]`; `nan` for constant data (zero variance).
- **Chi-square vs uniformity**: `Σ (O_i − N/256)² / (N/256)` with 255 degrees
  of freedom; computed on the ciphertext.
- **Throughput**: `file_size_megabytes / elapsed_seconds`, with
  **1 MB = 1,048,576 bytes** (fixed; set `benchmark.megabyte_bytes` to
  `1000000` for the decimal convention, consistently everywhere).
- **Ciphertext expansion**: `ciphertext_size − plaintext_size` in bytes
  (and as % of plaintext size); expected to be exactly 0.
- **Exact reconstruction**: SHA-256(plaintext) == SHA-256(decrypted),
  additionally confirmed by direct byte comparison. MD5 is recorded only as
  a legacy-compatibility secondary checksum.

## Benchmark protocol

- Per file: `timing_warmup_runs` untimed-in-statistics warm-up runs first,
  then `timing_repetitions` measured runs; **every measured run is a row in
  `raw_measurements.csv`** and the summary adds mean / sample standard
  deviation (ddof = 1) / median / min / max per timed series.
- `include_file_io_in_timing: true` times read + transform + write; `false`
  times only the in-memory transform (artifacts are still written outside
  the measured interval).
- Timings are wall-clock and **hardware/OS/interpreter dependent**; they are
  not comparable across platforms and must not be presented as
  cross-platform benchmarks.

## Limitations

1. **Not secure cryptography** — see the warning at the top. No resistance
   to known-plaintext/chosen-plaintext attacks is claimed or expected; the
   linear Hill stage leaks structure under such attacks.
2. **Keystream reuse**: a single fixed keystream (from the config's
   `logistic_r`/`logistic_x0`/warm-up) encrypts every file and every run —
   the classic two-time-pad scenario. Per-file nonce diversification is
   explicitly disabled in this baseline and flagged in
   `key_material_report.json` (`per_file_nonce_or_diversification: false`).
3. **Keystream prefix overlap**: the key matrix is derived from the first
   135 bytes of the same logistic orbit that later serves as the file
   keystream. This mirrors the studied scheme and is another documented
   weakness of the baseline.
4. **Finite-precision logistic map**: IEEE-754 orbits can enter short
   cycles and the quantized bytes are not uniformly distributed.
5. **Runtime results** are hardware-dependent (see *Benchmark protocol*).
6. **Synthetic test files** are placeholders with format-accurate magic
   bytes but SplitMix64 filler content. They reproduce the workflow, not the
   article's numeric byte statistics. Supply the original files in
   `data/input/` to reproduce the article's numbers.
7. Large inputs are slower than native ciphers because the keystream is a
   pure-Python orbit loop; this is part of what the experiment measures.
